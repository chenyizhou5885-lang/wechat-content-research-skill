# 公众号选题情报与写作 Skill

面向企业公众号的选题研究与中文成稿工作流。它把公开信号、行业问题、同类表达和企业一手材料组织成可复核的选题判断，并在证据充分时生成自然、具体的中文文章。

> 当前版本：`v0.7.1`  
> 创作者与维护者：[chenyizhou5885-lang](https://github.com/chenyizhou5885-lang)
>
> 创作背景：为句子互动创作
> 运行环境：面向 WorkBuddy Skill 机制设计

## 它解决什么问题

企业内容团队常见的困难不是“找不到文章”，而是很难判断什么值得写、依据是否可靠，以及怎样写出自己的观点。本 Skill 围绕下面这条链路工作：

```text
上游信号 → 管理或业务问题 → 具体场景 → 企业一手证据 → 差异化判断
```

它可以：

- 按行业和目标读者建立动态信源池，不依赖固定媒体名单；
- 追溯数字、预测、公司动作和引语的原始出处；
- 区分事实证据、同行表达观察与待核验线索；
- 对同类公众号内容进行文章级调研，识别已经被说透和仍被遗漏的部分；
- 在证据满足要求后，交付调研报告与自然中文成稿；
- 保留来源台账和校验结果，方便编辑、客户或团队复核。

## 三种工作深度

| 模式 | 适合场景 | 主要产出 |
| --- | --- | --- |
| `scan` | 快速寻找方向 | 一批标注“待验证”的选题线索 |
| `research` | 选题会、策略讨论、正式调研 | 可复核的研究报告与来源台账 |
| `writing` | 需要直接形成文章 | 研究报告、来源台账与文章成稿 |

`writing` 模式设有证据门槛。关键来源或公众号调研不足时，工作流会保留缺口并停止成稿，避免用搜索摘要或低质量转载补齐结论。

## 典型用法

导入 Skill 后，可以直接给出一个公司、账号或主题。例如：

```text
帮一家做组织协同软件的公司，扫描最近一年值得写的公众号选题。
```

```text
围绕“AI 进入销售管理”做一份能在选题会上使用的研究报告，关键数字要回到原始出处。
```

```text
研究同类公众号最近一年怎么写企业知识库，并为我们的账号写一篇文章。客户案例不能公开。
```

信息不足时，Skill 会先给候选项让用户选择；涉及客户授权、内部数据、产品露出比例或明确禁区时，会暂停并确认边界。

## 安装与运行要求

1. 将本仓库作为完整 Skill 目录导入支持 `SKILL.md` 的运行环境；不要只复制入口文件，`references/`、`scripts/` 和 `templates/` 都是工作流的一部分。
2. 本地脚本需要 Python 3；内置微信公众号搜索适配需要 Node.js。
3. WorkBuddy 中的公开网页发现与读取依赖宿主提供的 `WebSearch`、`WebFetch`。
4. Kimi WebBridge 仅是可选的本地增强，用于在可用时解析搜狗中转链接；未安装不影响基础调研，但相关公众号候选不能被当作已核验原文。

不同 WorkBuddy 版本的 Skill 导入和上架方式可能变化，请以平台当前文档与审核要求为准。本仓库公开不代表已经获得 WorkBuddy 官方收录、认证或背书。

## 本地校验

修改或发布前运行：

```bash
python scripts/validate_skill.py
python -m unittest discover -s tests -v
```

两项均通过后再打包或提交上架。

## 数据与内容边界

- 不在仓库中硬编码 Token、账号、Cookie、用户绝对路径或私有服务地址。
- 不把未经授权的客户资料、内部数据、商业秘密或个人信息写入公开文章。
- 不承诺覆盖全部公众号文章，也不把“没有搜到”解释为“对方没有写过”。
- 不复制参考文章原句、专属比喻、人物经历或可识别的段落结构，不模仿单一在世作者的声音。
- 使用外部材料时保留原始链接，并区分事实、转述和推断。
