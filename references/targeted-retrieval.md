# 定向召回与行业信源名单

## 核心原则

**拒绝要便宜，采纳保持昂贵。** 能靠一条规则、看一眼链接就排除的，绝不花成本打开；真要进正式台账的，核验一步都不能省。

## 先定向，再撒网

不要一上来就全网搜关键词，那样捞回来的东西质量不可控。顺序是：

1. **名单内定向**：把名单里的机构域名逐个做站内检索。
2. **动态机构**：本次选题涉及的监管部门、协会、研究报告、公司公告。
3. **全网兜底**：只用来发现名单外的重要来源。捞到好的，提名进名单。

站内检索的搜索次数和全网一样，但命中率高得多——域名约束本身就免费替你筛了一遍。

## 名单从哪来

**用户配置优先，现场生成兜底。** 有 `source_registry.json` 就先用它；没有就现场为这个行业生成一份，用完存下来复用。换行业整份替换，不要跨行业套用同一份名单。

skill 里存的是「怎么找出这个行业的头部」的方法，不是名单本身。不设跨行业永久白名单。

找头部的可靠信号，不靠模型印象：

- **头部产品**：最近一年的融资名单、行业榜单、大会赞助商名单。花钱办展、刚拿到钱的，基本就是当下的头部。
- **权威媒体和播客**：看这个行业的从业者在公开场合引用谁，投资机构的行业报告引用谁，创始人访谈发在哪。比「粉丝多少」准得多。
- **交叉引用**：一个来源被名单里多家反复引用，就该进名单。用「被引用」发现权威，这个信号最可靠，而且可以自动化。

## 名单会自己变准

每轮结束做两件事：

- 兜底层捞到的好来源写进 `nominated`，下轮进 `fixed`。
- `fixed` 里连续几轮没产出的（`misses_in_a_row` 累积）移出去。

这样名单越用越准，也不会僵化成一份老掉牙的媒体清单。

## 名单只管「捞得到」，不管「够不够格」

这条最容易搞错，单独强调：

**在名单里不代表够格当证据。** 头部产品的公众号发一篇讲市场规模的文章，它在名单里，但那个数字仍然必须回溯到原始报告。同类初创的官网讲自己的案例是一手材料，讲行业趋势就只是观点。

名单和 S/A/B/C 分级是两套独立判断。合并了就等于用名气代替质量。`build_sources.py` 里名单命中只影响覆盖率统计，完全不参与评级。

## 开页前先筛

拿到搜索结果列表，先跑预筛，再决定打开哪些：

```bash
python3 scripts/prefilter_candidates.py --candidates candidates.json --out filtered.json
```

会在开页之前扔掉：门户自媒体路径、聚合与低质域名、搜狗中转链接（必须先解析成真实微信地址）、超出时间窗口的、日期解析不出来的。

有校准样本时带上，用户标过「不要」的账号会被直接排除，标过「值得学」的会排在前面：

```bash
python3 scripts/prefilter_candidates.py --candidates candidates.json --profile calibration_profile.json --out filtered.json
```

**留下不等于采纳**，只是说这条值得花成本打开。

## 门禁看名单命中，不看读了几篇

覆盖率考核的是「名单里真读到几家」加「有几个原始出处」，不是「一共读了 8 篇」。8 篇什么来路无所谓的数量考核，换不来你想要的质量。

名单为空时这一条自动不生效——没有名单可命中，要求命中就是谁都过不去的空门禁。

## 中途查缺口，别等终点

```bash
python3 scripts/build_sources.py --raw raw_sources.json --interim
```

输出还缺什么，以及下一步最该补哪个。缺的往往是「一个 S 级源」，那就别再去凑第 12 条候选。

终点全有全无是最差的延迟模式：8 篇里开了 7 篇，整个门禁挂掉重来。
