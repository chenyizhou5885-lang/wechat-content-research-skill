# 内置搜狗微信文章搜索

## 作用

该脚本用于发现微信公众号候选文章，返回标题、摘要、公众号、发布日期和链接。它负责召回，不负责证明文章观点正确，也不保证覆盖全部公众号内容。

## 命令

默认只返回执行当天向前 365 天内、发布日期可解析的文章：

```bash
node scripts/search-wechat.js "关键词" -n 10
```

用户明确指定其他时间范围时：

```bash
node scripts/search-wechat.js "关键词" -n 10 --days 90
```

只对最终入选的少量文章解析并核验微信原文：

```bash
node scripts/search-wechat.js "关键词" -n 5 -r
```

`-r` 与 `--verify-browser` 等价。核验时会读取最终地址，并交叉检查标题、公众号、发布日期与正文。

## 核验强度按用途分级，不按条数

同一篇文章承担什么任务，决定了要核到多深。这是省时间最该省的地方。

| `role` | 用途 | 核验要求 |
| --- | --- | --- |
| `fact_source` | 支撑事实、数字、引语 | 真实微信地址 + 标题 + 账号 + 日期 + 正文可读 |
| `landscape_only` | 只用来看同行怎么讲这个话题 | 真实微信地址 + 标题 + 账号 + 日期，不必读全文 |

`landscape_only` 是关于内容景观的观察，不是事实判断，所以不需要付全文核验的成本。

**但它不能支撑任何 claim。** `build_sources.py` 里 `landscape_only` 出现在 `claim_ledger` 的 `source_ids` 中会直接判定该 claim 失败——要引用其中的事实，就得回到原始出处，把它按 `fact_source` 重新核一遍。不填 `role` 时默认按 `fact_source` 处理，也就是默认走严格路径。

## 读取微信原文

已经拿到真实 `mp.weixin.qq.com/s/...` 地址时，用宿主 `WebFetch` 直接读取即可，能拿到标题、发布时间戳和正文，不需要真实浏览器。

要注意两件事：

- 微信文章页 HTML 往往有几 MB，只提取标题、账号、日期和正文长度，不要整页带进上下文。
- 抓到「请在微信客户端打开」「环境异常」这类壳页时，说明没拿到正文，必须记为核验失败，不能拿壳页充当已核验。

搜狗返回的是中转链接而不是真实地址，直接请求会被反爬拦下。把中转链接解析成真实地址目前仍依赖 `-r`；解析不了就如实记为 `failed`，保留搜狗链接当待核验线索。

## 检索策略

围绕确定选题至少准备三组不同关系的检索词：

- 选题与业务问题词。
- 竞品/对标账号名加选题词。
- 上游概念、行业和岗位词。

不要只搜企业名称，也不要把一次搜索的前十条当成完整竞品研究。合并多组结果后按标题、链接和发布者去重，再进入来源分类和全文核验。

## 输出使用

- `published_at` 是经过解析的 ISO 时间，用于判断一年窗口。
- 未使用 `-r` 时，`url` 只是搜狗候选链接，`verification` 为 `candidate_only`。
- 使用 `-r` 后，成功结果的 `url` 和 `resolved_url` 是浏览器实际打开的微信原文地址，并包含 `verified_title`、`verified_account`、`verified_published_at_raw`、`body_text` 与 `body_length`。
- 搜狗候选链接可能带 `timestamp`、`signature` 等临时参数，不能写入正式报告充当可长期复核的原文链接。
- 搜索摘要只用于初筛，不作为事实证据，不用于语言风格抽象。
- 进入正式报告的文章必须进一步核验正文、发布日期与可访问链接。

## 失败与停止条件

- `returned` 为 0 时，先更换关键词或稍后重试一次。
- 遇到验证码、antispider、请求超时或页面结构变化时停止搜狗请求，改用普通网页搜索并在调研报告中说明渠道限制。
- 不高频调用，不批量抓取账号历史，不用旧文章补足数量。
- `-r` 会先检测 WebBridge；若已安装但未启动，脚本尝试启动并重试，把 `available / recovered / unavailable`、命令和错误写入 `tool_attempts`。它是可选本地增强，不是 WorkBuddy 内置能力。
- 无法解析真实链接或读取正文时，结果标为 `failed`，保留搜狗链接作为待核验线索；它不能计入完成的文章级来源。
- 公众号数据服务当前未作为 WorkBuddy Connector 集成，不得声称已自动调用。用户需要时按 WorkBuddy Connector 规范另行接入；接入后返回的结果同样要过正文与日期核验。
- 不得推荐自建 RSS 抓取方案：这类工具或限个人学习研究使用、禁止商用，或已停止维护。本 skill 只支持有正规商务授权的数据服务和用户自备材料两条路。

## 运行要求

- Node.js 18 或更高版本。
- 若需真实浏览器核验，应已安装并连接 Kimi WebBridge，或将等价浏览器能力作为正式 WorkBuddy Connector 提供。
- `wechat-search.bundle.cjs` 已包含运行依赖，用户不需要执行 `npm install`。
